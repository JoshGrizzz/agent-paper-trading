# 决策记录格式

每轮结束时，最终回复必须且只能包含一条符合本文件格式的决策记录。

账户余额、持仓、待结算方案和成交状态以 `./broker` 返回的结果为准。本记录仅用于保存决策过程，不能作为账户事实来源。

```md
## <美东时间 ISO 8601 时间戳>

### 本轮判断

- 市场与关键信息：
- 当前策略及主要理由：
- 主要风险：

### 资金与持仓检查

- `cash.available`：
- 主方案买入资金需求：
- Backup 1 买入资金需求：
- Backup 2 买入资金需求：
- 预计冻结现金：
- 卖出数量检查：各标的卖出总数是否均不超过其 `available_quantity`

### 本轮操作

- 提交交易方案：
  - 方案 ID：
  - 有效时间：
  - broker 整体结果：

  - 主方案：
    - broker 状态：accepted / rejected
    - 订单：
      - 操作：买入 / 卖出
      - 标的：
      - 数量：
      - 限价：
      - 订单 ID：

  - Backup 1：
    - broker 状态：accepted / rejected / 未提供
    - 拒绝原因：
    - 订单：
      - 操作：买入 / 卖出
      - 标的：
      - 数量：
      - 限价：
      - 订单 ID：

  - Backup 2：
    - broker 状态：accepted / rejected / 未提供
    - 拒绝原因：
    - 订单：
      - 操作：买入 / 卖出
      - 标的：
      - 数量：
      - 限价：
      - 订单 ID：

- 撤销交易方案：
  - 方案 ID：
  - broker 结果：

- 不操作：
  - 原因：

### 后续计划

- 下轮重点检查：
```

## 填写规则

- 时间戳必须使用当前轮次给出的美东时间，并保留 UTC 偏移量。
- “提交交易方案”“撤销交易方案”和“不操作”至少填写一种；不适用的部分可以删除。
- 主方案和每个 backup 内有多笔订单时，应逐项重复完整的“订单”字段。
- 主方案的订单数量不设上限；最多只能提供两个 backup 方案，每个 backup 内的订单数量不设上限。
- 每个候选方案的买入资金需求必须填写为该候选内所有买单的 `Σ(数量 × 限价)`；没有买单时填写 `0.00`。
- 主方案和每个 backup 必须分别满足“买入资金需求不超过 `cash.available`”，不得把预计卖出收入计入可用现金。
- “预计冻结现金”填写所有被 broker 接受的候选方案买入资金需求的最大值，而不是三者之和。
- 对每个候选方案分别汇总每个标的的卖出数量，并确认其不超过 status 返回的 `available_quantity`。
- Agent 填写的预算只用于说明；账户校验和最终冻结金额始终以 broker 返回结果为准。
- 必须如实记录 broker 对主方案和每个 backup 分别返回的 `accepted` 或 `rejected`。某个 backup 被拒绝不代表整个交易方案被拒绝。
- 被拒绝的候选方案没有交易效力；没有方案 ID 或订单 ID 时填写“不适用”。
- “买入”表示建立或增加多头持仓。
- “卖出”仅表示减少已有多头持仓，不允许建立负持仓。
- 买入反向或杠杆 ETF 时，操作仍填写“买入”。
- 尚未由 `./broker` 确认的成交不得写成已经成交。
- 内容应简洁，保留足以支持下一轮继续决策的信息。
